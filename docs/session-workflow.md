# Session Workflow

This is the canonical operating procedure for creating, generating, and sharing an Awepeeps Archipelago session. Use `just` for every repository workflow; scripts remain implementation sources behind the recipes. Install Python, Git and `just` 1.33 or newer, then run `just setup` from the repository root. Paths are relative to that root unless absolute.

Set variables before the recipe name: `just season="2026/3. Fall" archipelago="<installed-directory>" generate --dry-run`. The default season is `2026/3. Fall`; `archipelago` defaults to `C:/ProgramData/Archipelago` on Windows. macOS and Linux users must supply their actual installation path. `input` and `output` default to the selected season's `YAML` and `.secrets/hidden` directories and can also be overridden. Arguments after the recipe name pass through as positional arguments, including quoted paths with spaces. `just --list` lists all recipes.

## Layout

Each season follows this shape:

```text
2026/<number>. <Season>/
  README.md
  YAML/.host.yaml
  YAML/<player>_<game>_vN.yaml
  APWorld/<world>.apworld
  .roms/                         local only, ignored
  .secrets/hidden/<run-id>/      private generation workspace, ignored
  .secrets/revealed/<run-id>/    intentionally shared artifacts
```

`YAML/.host.yaml` is a host configuration, not a player file. Its `Players` and `output` paths are relative to the installed Archipelago directory. Do not copy it into a player folder or treat repository-relative paths as Archipelago paths.

## Local inputs and worktrees

A root `.worktreeinclude` lists repo-relative paths for local-only inputs that a new worktree needs to generate: the season `.roms/` stashes, the root `.admin/` folder, and the bot's `bridgeipelago/config.json`. Season ROM stashes are listed as folders so a ROM added later is picked up automatically. The file is tracked, but every path it lists is gitignored, so it references local files without committing them.

`bridgeipelago/config.json` is the only bot file listed, because it holds the credentials that are configured once. The bot's data folders and `.venv` are rebuildable by re-cloning, so they are not copied. See [Discord bot](discord-bot.md).

Keep the following out of `.worktreeinclude`, and keep the reasons with the file:

- `.venv/` — a machine-specific virtual environment. It is ignored by its own internal `.venv/.gitignore`, not by the repository `.gitignore`.
- `scripts/__pycache__/` — regenerated by any Python run.
- `.playwright-cli/` — scratch output, not an input.
- `.secrets/hidden/` — a private generation workspace. Copying one into a new worktree makes `just generate` refuse to reuse an existing workspace directory.
- `.generated-secrets-hidden/` — secrets; never copy them around.

`.worktreeinclude` is a declaration of local intent. The repository scripts do not read it, so a worktree that needs ROMs still gets them by copying from a checkout that has them.

## Check local setup

Run `just doctor` to inspect the local Git checkout, status, remotes and worktrees without fetching, switching branches or printing remote URLs. Use the intended checkout and preserve unrelated changes before proceeding.

To check the bot configuration, supply its actual private path; paths with spaces are supported:

```powershell
just config-check "private bot/config.json"
```

The doctor and config-check recipes accept `--repo <checkout>` to override the inspected root; a relative config path resolves against that root. Neither starts the bot or contacts Discord or Archipelago. Diagnostics name invalid keys without printing tokens, passwords, IDs or raw config values. They check local shape and required session settings, not whether credentials authenticate or a live room is correct. `ExpectedSeedName` must come from the trusted original `AP_<seed_name>.archipelago` filename; add `--expected-seed <trusted-name>` to config-check for exact comparison without echoing it. Set `DailyPostConfig.DeathLinkSlots` to exact participating slot names, `[]` when no games participate, or `null` when unknown. Unknown must never be treated as completed.

`just check` runs the validator, compiles the scripts and runs the offline tests. `just smoke` exercises actual recipes using isolated argument-forwarding fixtures and offline CLI help checks. CI runs these checks on Windows, macOS and Linux; it does not generate a real game or host a room. Real generation requires a usable Archipelago installation, reviewed APWorlds and local ROMs where required. Hosting requires network access and admin credentials. `just secrets` runs installed Gitleaks v8 with fully redacted findings and fails if Gitleaks is missing. CI also scans full Git history using a pinned standalone Gitleaks CLI without uploading a report. Inspect private files only locally; do not paste raw config or scanner reports into a review.

## Create a season

Use `just scaffold` when starting a new season or importing a group of local inputs. It refuses to overwrite an existing season, rejects duplicate player aliases, verifies APWorld ZIP integrity, and copies local ROMs into the ignored `.roms/` directory.

Start with a dry run:

```powershell
just scaffold --season "2026/4. Winter" --template-season "2026/3. Fall" --player "local inputs/player.yaml" --apworld "local inputs/world.apworld" --rom "local inputs/game.z64" --dry-run
```

Use `--host-yaml` instead of `--template-season` when a specific host file is available. Repeat `--player`, `--apworld`, and `--rom` as needed. Review the printed mapping, then rerun the same command without `--dry-run`. The scaffold copies YAML bytes without changing game options, creates the standard folders, and writes a starter season README.

Active-season player YAMLs must already have literal names. A file with `name: "{player}"` or `name: "{number}"` is not ready for an active season; assign the real alias and verify preserved settings with `just compare <before> <after>`. The [comparison implementation](../scripts/compare_player_yaml.py) documents the metadata exclusions.

Run the repository check immediately after scaffolding:

```powershell
just check
```

## Generate privately

Always preflight first. This reads only the selected season's YAML and APWorld inputs and skips `game: TBD` players:

```powershell
just season="2026/3. Fall" archipelago="C:/ProgramData/Archipelago" generate --dry-run
```

After reviewing the player list and generator command, remove `--dry-run`. Use an explicit unique `--run-id` for named or repeated runs. Select other player/output folders with `just input="<player-yaml-dir>" output="<workspace-root>" generate --dry-run`. If the date-only default already exists under either `.secrets/hidden/` or `.secrets/revealed/`, generation requires an explicit new ID. Use `--seed <number>` only when a known numeric seed is required. Use `--sync-apworlds` only after reviewing the checked-in archive and its source; the default behavior stops on missing or different installed APWorlds.

The generator copies `YAML/.host.yaml` to the private workspace as `host.yaml` and runs `ArchipelagoGenerate` with that workspace as its current directory. Archipelago therefore loads omitted generator defaults, including spoiler level, from that copied file; a command-line option such as `--spoiler 1` overrides the corresponding host setting.

The completed run stays private under `.secrets/hidden/<run-id>/` and contains:

- `Players/` with the playable YAML copies
- `host.yaml` and `generation-manifest.json`
- `output/` with Archipelago's raw output
- `YYYY-MM-DD_seed.zip` and `YYYY-MM-DD_spoiler.txt` staged for publication

The manifest records input hashes, the installed Archipelago version, the generator hash, and the command. Keep it with the private run when reproducibility or debugging matters. `just publish <run>` rechecks the manifest structure and the player, APWorld, and host input hashes before copying artifacts.

## Host the room

Hosting is the standard step right after a successful generation. It uploads the run's seed to archipelago.gg as a room owned by the admin session stored in the ignored `.admin/session_id.env` (`SESSION_ID=<uuid>`, the same file `.admin/open-session.cmd` opens), so that session sees the room log and can run admin commands. If the browser is signed in to a different session, open `https://archipelago.gg/session/<SESSION_ID>` or update the env file before hosting.

Always dry-run first:

```powershell
just season="2026/3. Fall" host 2026-10-17 --dry-run
```

After review and authorization for the network upload, remove `--dry-run`:

```powershell
just host 2026-10-17
```

The script requires HTTPS except for localhost, and strips the `*_Spoiler.txt` entry from the upload by default, because archipelago.gg otherwise serves the spoiler as a public download on the seed page. Use `--include-spoiler` only for a run whose spoiler is already revealed. It records the result in `room.json` inside the private run. If room creation succeeds but reading its page fails, it keeps a partial record with `complete: false` and prints the room URL; rerunning reports that incomplete record and does not create another room unless `--force` is given. A completed record has `complete: true`. After hosting, update the season README Session Links with the room URL (never the seed URL) and point the Discord bot at the room. Room owners can use the [Admin guide](admin-guide.md) for commands in the hosted server console.

## Publish deliberately

For a retained private run, validate and publish both artifacts together:

```powershell
just season="2026/3. Fall" publish 2026-09-20_test --dry-run
just season="2026/3. Fall" publish 2026-09-20_test
```

If the private run has already been removed, provide explicit staged files instead:

```powershell
just season="2026/3. Fall" publish-files --seed "private files/2026-09-20_seed.zip" --spoiler "private files/2026-09-20_spoiler.txt" --destination 2026-09-20_test --dry-run
```

The publisher requires matching `YYYY-MM-DD` names, a readable and intact seed ZIP, a non-empty UTF-8 spoiler, and no ROM-like entries inside the seed. Publication and repository validation also inspect supported binary multidata for embedded credentials; opaque or unsupported data cannot silently pass that gate. Follow the command's actionable refusal rather than assuming a binary seed contains no secrets. It refuses to overwrite existing artifacts unless `--overwrite` is explicit. It copies into `.secrets/revealed/<destination>/`; it does not delete the private source.

The data-only parser also bounds hashing work for dictionary keys and set members; integer keys above 128 bits and excessively nested or colliding keys fail closed. These limits prevent small malicious payloads from exhausting publication or CI resources.

Only publish a spoiler when the group intentionally wants it revealed. A hosted session normally needs the seed archive, while the spoiler remains a deliberate disclosure choice.

## Discord tracking bot

A session may run the self-hosted `bridgeipelago` bot for live check, death, and hint activity in Discord. It connects as a spectator slot, so its YAML is a normal season player input. Hosting, configuration, and the secrets boundary are documented in [Discord bot](discord-bot.md).

## Close or archive a season

Start with a read-only closure plan for a specific run:

```powershell
just season="2026/3. Fall" close-session 2026-10-17
```

The recipe uses the configurable `season` variable and always supplies dry-run mode; it has no execution mode, network option, service control or Git cleanup behavior. It reports whether the private run and revealed archive exist and lists the remaining decisions. Tracker verification remains pending until separately performed with explicit network opt-in: check the intended seed, final player goals and location totals, and the exact DeathLink participants. Do not infer goal completion from check counts alone.

After verification, publish only artifacts the group has chosen to reveal using the publisher dry run and credential gate. Update the season README status and final room/session links manually. After explicit authorization for the identified bot runtime, stop **and disable** its service (or equivalent container restart policy), then verify it stays stopped across reboot. Follow the deployment procedure in [Discord bot](discord-bot.md). Retain private source artifacts until the archive is verified; delete private work only when specifically authorized. Preserve historical YAML settings, README tables, unrelated changes and feature branches.

Finish with:

```powershell
just check
just smoke
git diff --check
```

The validator is the repository gate. If it fails, fix the underlying input or report the failure; do not weaken the check or force ignored/private files into Git.
